# Beautify GitHub README（美化 GitHub 个人主页）

## 一句话定位

把平淡的 GitHub 个人主页 README 变得好看、专业、有吸引力——不改实质内容，纯视觉增强。

## 适用场景

- 用户的 GitHub 个人主页 README 看起来太朴素，只有纯文字。
- 用户想让自己的 profile 更专业、更有技术感。
- 用户想加 GitHub 统计卡片、技术徽章、打字动画等动态元素。
- 用户想重新组织已有内容的视觉布局（居中、分层、分割）。

## 不适用场景

- 改的是项目 README 而非个人主页 README——项目文档有不同的美化标准。
- 用户想修改**实质内容**（项目说明、技能列表、经历等）——本 Skill 做视觉叠加，不改内容本身；内容修改应走常规编辑。
- 用户需要完整的设计品牌重塑——这是小范围美化，不是品牌级设计。

## 执行前需要的信息

- 用户 GitHub 用户名。
- 对现有 README 的访问权限（Skill 会自己读仓库文件）。
- 用户偏好的风格方向（如果知道的话）。

## 执行流程

1. 读现有 README，分析内容结构。
2. 提出 2-3 种美化方向让用户选。
3. 在用户选定方向后，不改实质内容，叠加徽章、统计卡片、排版优化、布局调整。
4. 展示 diff 或预览，用户确认后交付。

## 交付结果

- 美化后的 `README.md`。
- 设计决策的简要说明。
- 可选的"之后自己怎么改"维护指南。

## 默认边界

- **读文件**：是。
- **写文件**：是（只写 README.md）。
- **执行命令**：否。
- **网络**：否（引用的徽章和卡片都是外部 URL，由 GitHub 渲染时自己请求）。
- 不改实质内容。不加收费服务。徽章和卡片只用免费开源工具。

## 行为案例

### 案例 1：典型成功场景

**输入**：用户说「我 GitHub 主页太丑了，帮我弄好看点」。现有 README 是一段纯文字自我介绍 + 技能列表。

**预期行为**：
1. 读现有 README。
2. 识别内容只有纯文字。
3. 提出 2-3 种美化方案（如：加头部横幅和技术徽章 + GitHub 统计卡 + emoji 分割排版）。
4. 用户选方向后，改写 README——保留原有自我介绍和技能列表，叠加徽章、统计卡片、分割线。
5. 展示效果，确认后交付。

### 案例 2：边界/失败场景（已有丰富视觉元素）

**输入**：用户说「帮我美化 README」。但现有 README 已经有大量徽章、统计卡、图片、动态 SVG。

**预期行为**：
1. 读 README，发现已经很丰富。
2. 告知用户：「你的 README 已经有比较完善的视觉元素了。有没有具体想改的地方？比如换个风格、调整布局、减少一些元素？」
3. **不得**强行叠加更多元素导致视觉过载。
4. **不得**为了实现"美化"而把已有好东西去掉。
