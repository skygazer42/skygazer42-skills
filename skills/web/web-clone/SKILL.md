# 网站 1:1 复刻

**核心哲学：逐行为对齐，不是"做一个像的"。源站有的都要有，源站没有的不做，所有代码可溯源到原始产物。**

> **最重要的一条规则：镜像里有线索的按线索恢复，没线索的不要瞎猜。** 猜出来的东西会偏离源站，且难以发现。宁可标记「待查」，也不要编一个看起来合理的实现。

## 何时使用

- 用户想 1:1 复刻一个线上网站（学习、迁移、逆向）。
- 需要在没有源码的情况下从编译产物重建工程。
- 站点重度使用 WebGL/Canvas/自研引擎，无公开文档。

## 不适用场景

- 从零做**原创**设计——那是 `web.frontend-design`（复刻要精确对齐，设计要创意自由，是相反的意图）。
- 只想实现一个新 UI 功能——`web.frontend-implementation`。
- 复刻明确侵权且用于商业用途——先解决授权（见「边界」）。

## 四步法

### 1. 镜像（Mirror）

完整抓取站点的一切：HTML、CSS、JS bundle、图片、字体、模型、贴图、worker、WASM。存入 `legacy-mirror/` 作为**逆向的唯一依据**。

**三类常被漏掉的资产**（桌面爬取抓不到，要专门补录）：
- **Worker 运行时才 fetch 的**：WASM、动态 import 的 chunk。
- **懒加载的**：滚动/交互才请求的画廊图、视频、次级模型。
- **移动端专属变体**：`_MOBILE` 低清资源、粗指针分支专属路径。

发现缺口时**从源站补录**，别用桌面版凑合——粗指针视口下的 404 会让整个初始化崩掉。

### 2. 逆向（Reverse）

分析技术栈，理解站点怎么搭的。

- **压缩 bundle 用 beautify 展开**成可读代码（压缩≠加密，通常可读）。逐字节混淆的另说，但大多数是可读的。
- 逆向出：构建工具、框架、渲染主体、私有数据格式、状态管理、动画/滚动系统、渲染管线拓扑。
- **私有格式往往比预期简单**——先花时间逆向清楚（写成一份 `engine-notes.md`），再动手移植。盲目动手会反复返工。

### 3. 严格溯源移植（Sourced Port）

- **工程骨架可以换**（换成 Astro/Vite/TS 等现代工程），但**核心逻辑逐类逐函数对照原 bundle 移植**。
- **Shader/GLSL/关键常量从 bundle 逐字提取**，不做"优化"或近似。
- **连死代码也按原样保留**。源站的 bug、错位赋值、无用参数——照抄。"修正"它们反而会偏离源站的实际渲染结果。真实案例：源站一个 `format = "R8"` 赋在了错误的对象上（no-op），"修好"它画面就变了。
- 关键数值（帧区间、相机参数、阈值）**必须从 bundle 读出**，不能猜。真实案例：某手部动画帧区间实为 71/116，凭感觉猜的 47 是错的。

### 4. 里程碑推进 + 三重验证

分里程碑推进（引擎核心 → 场景/模块 → 交互驱动 → 站点外壳）。**每个里程碑三重验证：**

1. **全新加载验证**——刷新页面从头跑，**绝不手动切换效果/状态**。手动切换会掩盖初始化状态 bug（未初始化字段 → NaN 传染 → 整屏崩坏，只有全新加载才暴露）。
2. **无头浏览器回归**——脚本驱动（puppeteer 等），桌面 + 移动仿真两条分支，检查零控制台报错。
3. **与源站并排像素比对**——同视口、按模块对齐的多个滚动点截图，**量化**核对（连平均亮度都对到 ±0.5）。

## 铁律（踩坑提炼）

| 铁律 | 为什么 |
| --- | --- |
| **没线索不瞎猜** | 猜的实现偏离源站且难查；宁标「待查」 |
| **目测像素会骗人** | 用脚本量截图做量化比对，别靠眼睛 |
| **全新加载才验收** | 手动切换掩盖初始化 bug；刷新从头跑 |
| **死代码照抄** | "修正"源站的 bug/错位赋值会偏离其真实结果 |
| **缺资产从源站补** | 镜像常漏 worker-fetch / 懒加载 / mobile 变体 |
| **私有格式先逆向再动手** | 写清 engine-notes 再移植，避免反复返工 |
| **色彩空间/字体竞态等隐蔽差异靠真机比对** | 少一行 `colorSpace` 赋值、字体未就绪就测量，都靠对比才发现 |
| **后台标签页 RAF 节流是环境问题** | 无头验证兜底，别误判为代码 bug |

## 收尾抓 bug

里程碑推完，仍会有很多 bug。剩下的像测试一样**目视抓 bug**：全新加载、逐模块过、记下不对的地方、对照镜像找线索修。可以让 AI 截图比照（更准但慢）。

## 边界与授权

- **网络**：抓取源站资产（镜像阶段）。
- **写文件**：重建工程代码。
- **执行命令**：构建、无头浏览器验证、截图比对。
- **授权风险 > 技术风险**：源站的模型、贴图、文案、品牌、字体授权通常归原作者。技术上可 1:1，但**公开部署/商用前必须先有授权**。默认按「个人学习研究、不公开部署」处理，并在产物里保留此声明。

## 与相邻 Skill 的区别

| Skill | 意图 |
| --- | --- |
| `web.web-clone` | **精确复刻**已存在的站——不要创意，要 1:1 溯源 |
| `web.frontend-design` | **原创精品设计**——创意自由、跳出框架 |
| `web.frontend-implementation` | 实现一个新 UI 功能（非复刻整站） |
| `web.frontend-testing` | 浏览器验证——复刻的三重验证可调用它 |
