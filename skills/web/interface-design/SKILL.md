# 产品界面设计

设计对外的 SaaS 应用、产品界面、数据看板、工具类产品。**核心取向：好用为先——一致、可预测、高效（「最少惊讶」）——但作为对外产品，也要有恰当的品牌感和打磨**，因为客户会流失、会用脚投票。对标 Linear / Stripe / Notion 那种「漂亮又好用的系统」。

> 谱系定位：营销/创意网页（`web.frontend-design`）追求视觉冲击；**本 Skill（SaaS 产品）在好用的基础上要品牌打磨**；企业内部系统（`web.enterprise-design`）比本 Skill 更极端克制、几乎不要品牌感。给数据密集的工作界面搞实验性排版是灾难，但纯粹朴素也会输给对手——SaaS 产品在两者之间。

## 何时使用

- 后台管理、admin panel。
- SaaS 应用主界面、数据看板 / dashboard。
- 内部工具、开发者工具、配置界面。
- 任何信息密集、以「完成任务」为目标的界面。

**不适用：** landing page、作品集、营销站、产品发布页——那些要视觉冲击，用 `web.frontend-design`。

## 设计原则

**信息密度与层级。** 系统界面通常信息量大。用层级（字号、字重、颜色、间距）而非留白堆砌来组织。一屏能看到的有用信息越多越好，但要有清晰的扫描路径——用户的眼睛应该知道先看哪里。

**一致性高于新颖。** 同一个操作在任何地方长得一样、行为一样。按钮、表单、表格、弹窗、导航——建立一套模式并处处复用。用户学一次，处处会用。**这里「最少惊讶」是最高美德。**

**建立设计 token 与组件系统。** 间距用一套尺度（如 4/8/12/16/24/32）、颜色用语义化 token（`text-primary`/`surface`/`border`/`danger`）、字号用固定阶梯。不要每个页面即兴发挥。对标 Ant Design / Material / Carbon 那种系统化，而非每页独立设计。

**数据展示是核心能力。** 表格（排序、筛选、分页、密度切换、空状态）、图表（选对图表类型、清晰的轴和图例）、指标卡、状态标签。数据密集界面的成败在这里。

**状态完备。** 每个交互覆盖：加载、空、错误、成功、禁用、部分加载、无权限。系统界面的空状态和错误态尤其重要——它们是给方向的时刻，不是装饰。

**导航与信息架构。** 侧边栏 / 顶栏 / 面包屑 / 标签页——让用户始终知道自己在哪、能去哪。深层级要有清晰的回路。

**表单是重灾区。** 清晰的标签（不靠 placeholder 当标签）、就近的校验反馈、合理的默认值、分组与分步、危险操作二次确认。

## 图标与克制

- 统一使用 [Lucide](https://lucide.dev) 图标——一致、专业、克制。
- 中文界面排版纪律、以及（克制的）动效工艺，参考 `web.frontend-design` 的 references（`chinese-typography.md` / `motion-craft.md`）。
- **界面禁止使用 emoji。**
- 克制动效：系统界面的动效服务于「反馈」和「连续性」（状态切换、展开收起），不是炫技。快、轻、可预测。尊重 `reduced motion`。

## 质量底线

- 响应式（系统界面尤其要处理好宽表格在窄屏的降级：横向滚动 / 卡片化 / 列优先级）。
- 键盘可达（表格、表单、弹窗的焦点管理和快捷键）。
- 可访问性：语义 HTML、可见焦点、对比度、屏幕阅读器标签。
- 性能：长列表虚拟化、大数据分页、避免不必要的重渲染。

## 与相邻 Skill 的边界

| 你要做的 | 用哪个 |
| --- | --- |
| 对外 SaaS/产品界面（好用 + 品牌感） | **本 Skill**（interface-design） |
| 企业内部系统（ERP/政企/后台，极致克制） | `web.enterprise-design` |
| 营销/创意网页（视觉冲击） | `web.frontend-design` |
| 把界面设计落地为可运行前端、连 API、覆盖状态 | `web.frontend-implementation` |
| 审查前端代码的正确性、无障碍、性能 | `web.frontend-review` |

**本 Skill 定系统界面的设计方向和规范，落地交给 `web.frontend-implementation`。**
