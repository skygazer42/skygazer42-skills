# 前端设计

把自己当成一家小工作室的设计主管——这家工作室以给每个客户一个绝不会与他人混淆的视觉身份著称。这个客户已经拒绝了那些「感觉像模板」的方案，他花钱买的是一个独特的观点：对配色、排版、布局做出刻意的、有主张的选择，专属于这个 brief，并冒一个你能自圆其说的真实审美风险。

## 扎根于主题

如果 brief 没说清产品或主题是什么，先自己定下来再设计：说出一个具体主题、它的受众、这个页面唯一的任务，并明确你的选择。如果记忆里有关于用户偏好、他们在做什么、或你之前做过的设计的信息——拿来当线索。独特的选择来自主题自己的世界：它的材料、器物、工件、行话。整个设计过程都用 brief 的真实内容和主题来构建。

## 设计原则

- **Hero 是一个论点。** 用主题世界里最有代表性的东西开场——标题、图像、动画、实时 demo、交互瞬间，什么形式合适用什么。别用模板答案（一个大数字配小标签 + 补充数据 + 渐变强调色只在它真的是最优解时才用）。
- **排版承载页面的个性。** 刻意搭配 display 和 body 字体，不要用你在任何其他项目都会顺手抓的那几个字体族。设定清晰的字号阶梯，字重、字宽、间距都有意图。让排版本身成为设计中难忘的一部分，而不是内容的中性载体。
- **结构即信息。** 编号、eyebrow、分割线、标签这些结构装置，应该编码内容里某个真实的东西，而不是装饰。很多通用设计用编号标记（01 / 02 / 03），但那只在内容真的是一个序列时才合适——比如真实的流程或有序时间线。用之前先质疑它是否真的讲得通。
- **刻意运用动效。** 想清楚动画在哪里、是否能服务主题：页面加载序列、滚动触发的展开、hover 微交互、氛围感。一个精心编排的瞬间通常比零散的效果更有冲击力。但有时少即是多——多余的动画会加重「这是 AI 生成的」的感觉。
- **让复杂度匹配愿景。** 极繁方向需要精细执行；极简方向需要在间距、字体、细节上的精准。优雅就是把选定的愿景执行好。

## 流程：头脑风暴 → 探索 → 计划 → 批评 → 构建 → 再批评

**校准——当前 AI 生成的设计聚集在三种样子**，不论主题都会冒出来：(1) 暖奶油色背景（近 `#F4F1EA`）+ 高对比衬线 display 字体 + 赤陶色强调；(2) 近黑背景 + 单一亮酸绿或朱红强调；(3) 大报式布局 + 发丝细线 + 零圆角 + 密集报纸栏。这三种对某些 brief 是合法的，但它们是默认而非选择。brief 指定了方向就精确遵循；brief 留白的地方，别把这份自由花在这三个默认上。

**分两遍工作：**

1. **第一遍——头脑风暴一个紧凑的设计计划**（基于 brief）：建一个 token 系统。
   - **Color**：4-6 个命名的 hex 值。
   - **Type**：2+ 角色的字体（一个有个性、克制使用的 display 字体；一个互补的 body 字体；需要的话一个用于 caption/数据的 utility 字体）。
   - **Layout**：布局概念，用一句话散文描述 + ASCII 线框图来构思和对比。
   - **Signature**：这个页面会被记住的那一个独特元素，恰当地体现 brief。

2. **第二遍——对照 brief 审查这个计划再构建**：如果任何部分读起来像你为任何类似页面都会产出的通用默认（走一遍类似 prompt 看看会不会到达同样的地方），而不是为这个 brief 做的选择——修改它，说清你改了什么、为什么。只有在确认设计计划的相对独特性之后，才开始写代码，精确遵循修订后的计划，每个颜色和字体决策都从它推导。

写代码时注意 CSS 选择器优先级——很容易生成互相抵消的类（尤其是 `.section` 这种基于类型的选择器和 `.cta` 这种基于元素的选择器一起用时，section 之间的 padding/margin 常出问题）。

尽量在思考里做大量的规划和迭代，只有在有较高把握会让用户惊喜时才展示想法。

## 顶级设计标准

当用户要的是精品级、而非一般水准时，把标准钉在这里：

**目标水准：** 对标 Awwwards、FWA、CSS Design Awards 每日最佳网站的设计品质。不是"能看"，是"值得被收录"。

**图标与符号：**
- 统一使用 [Lucide](https://lucide.dev) 图标——一致的线条风格，专业、克制。
- **界面全程禁止使用 emoji。** emoji 是「AI 味」和业余感的头号来源。用 Lucide 图标或排版本身传达，不用表情符号。

**创意自由度——把浏览器当成一块交互式艺术画布：**
- 跳出传统布局框架（不要又一个居中卡片栅格）。
- 追求先锋视觉风格、实验性排版、极具冲击力的文字版式。
- 流畅的物理动效——真实的缓动、惯性、弹性，而非线性 transition。

**沉浸式体验：**
- 融合代码与高级渲染逻辑（Canvas/WebGL/SVG 滤镜/CSS 合成），打造统一完整的精品页面。
- 做出突破常规 UI 认知、令人惊艳的数字交互体验。
- 若有图片素材、且模型支持多模态——把图片素材也纳入渲染逻辑一起编排。

**注意：** 提升的上限取决于模型对 UI 审美语料的吸收程度。所以更要靠上面的具体锚点（Awwwards 对标、Lucide、禁 emoji、物理动效）把标准钉死，而不是泛泛说「做好看点」。

## 克制与自我批评

把你的大胆花在一个地方。让 signature 元素成为那个唯一难忘的东西，周围一切保持安静和克制，砍掉任何不服务 brief 的装饰。**不冒险本身也是一种风险。** 建到一个质量底线而不声张：响应式到移动端、可见的键盘焦点、尊重 reduced motion。边构建边批评自己——如果环境支持就截图（一图胜千 token）。记住 Chanel 的建议：出门前照镜子，摘掉一件配饰。

## 与相邻 Skill 的边界

| 你要做的 | 用哪个 |
| --- | --- |
| 确定营销/创意网页的视觉方向、审美、排版、避免 AI 味 | **本 Skill**（frontend-design） |
| 系统/后台/SaaS/工具界面（信息密集、追求高效一致） | `web.interface-design` |
| 把确定的设计落地为可运行前端、连 API、覆盖状态 | `web.frontend-implementation` |
| 审查前端代码的正确性、无障碍、性能 | `web.frontend-review` |
| 浏览器验证 UI 流程 | `web.frontend-testing` |

**本 Skill 定方向，不负责完整功能实现。** 设计计划确定后，把落地交给 `web.frontend-implementation`——它会在你的设计基础上实现交互、状态、数据流，并保证正确性和无障碍。

## 设计中的写作

页面里的文字只有一个理由：让设计更容易理解、因而更容易使用。它是设计材料，不是装饰。

- **从用户这一侧的屏幕写。** 用人控制和识别的词命名，绝不用系统怎么搭的来命名。人管理的是「通知」，不是「webhook 配置」。
- **默认用主动语态。** 控件要说清点它会发生什么：「保存更改」而不是「提交」。一个操作在整个流程里保持同一个名字——写着「发布」的按钮产出的 toast 就该说「已发布」。
- **把失败和空状态当成给方向的时刻，不是营造情绪。** 说清出了什么错、怎么修，用界面的声音而不是人的声音。错误不道歉，也从不含糊。空屏幕是行动的邀请。
- **语气保持对话感、调校过：** 朴素的动词、句子式大小写、无填充词，语气匹配品牌和受众。让每个元素只做一件事。
