# 企业系统设计

设计公司/企业内部系统——ERP、内部管理系统、政企办公、业务工作台。**比 SaaS 产品界面更极端的克制**：几乎不要品牌表达、不要打磨感、不要取悦。用户是**被迫使用的员工**，衡量标准只有三个：**高效、不出错、低培训**。

> 与 `web.interface-design` 的关系：本 Skill **建立在 interface-design 的全部通用系统原则之上**（信息密度、一致性、设计 token、数据展示、状态完备、信息架构、表单——见 `web.interface-design`，此处不重复）。本 Skill 只讲**企业内部系统特有的、更极端的取向和专属关注点**。

## 核心取向：被迫使用的用户

SaaS 产品的用户可以流失，所以要好用**又**有品牌感。企业内部系统的用户是员工——没得选。这翻转了很多决策：

- **不需要取悦，需要不挡路。** 去掉一切装饰性视觉、品牌表达、"惊喜"动效。近乎「无设计的设计」。
- **低认知负荷 > 美观。** 专业用户每天用 8 小时，密度和效率压倒一切。宁可密集专业，不要疏朗好看。
- **低培训成本是硬指标。** 符合企业已有系统的惯例，让用户零学习迁移。**不要创新交互**——用户不想学新东西。
- **稳定 > 新颖。** 企业软件生命周期长（5-10 年），保守选型，不追潮流。

## 企业专属关注点

这些是 SaaS 产品设计通常不深入、但企业系统绕不开的：

| 关注点 | 说明 |
| --- | --- |
| **角色与权限（RBAC）** | 复杂的角色矩阵，界面随角色动态变化；权限不足时优雅降级（隐藏 vs 禁用 vs 提示申请），不是简单藏起来 |
| **审计与可追溯** | 操作日志、变更历史（谁、何时、改了什么、改前改后）、可回溯；关键操作留痕 |
| **遗留兼容** | 旧浏览器支持（可能含 IE/旧版内核）、与已有企业系统集成、既定数据格式对接 |
| **合规** | 无障碍是法规要求（等保 / WCAG 强制，非加分项）、数据隐私、行业规范 |
| **批量操作** | 大批量数据的多选、批处理、导入导出、批量校验与错误回报 |
| **密集表格与表单** | 一屏塞大量字段和数据列，专业用户要密度；多级表头、冻结列、行内编辑 |

## 视觉基线

- 中性、低饱和的配色；克制到近乎朴素。品牌色只用在最小必要处（logo、主操作）。
- 统一 [Lucide](https://lucide.dev) 图标，**禁 emoji**。
- 中文界面排版纪律参考 `web.frontend-design` 的 `references/chinese-typography.md`；企业系统动效极克制，动效工艺见其 `references/motion-craft.md`。
- 动效只服务于反馈和连续性（保存中、展开收起），快到几乎无感。绝不炫技。
- 对标 **SAP Fiori / IBM Carbon / Ant Design Pro / Salesforce Lightning / 微软 Fluent（企业侧）**，而非 Linear/Stripe 那种有品牌打磨的 SaaS。
