# Enterprise Design（企业系统设计）

## 一句话定位

设计公司/企业内部系统——ERP、内部管理、政企后台、业务工作台。比 SaaS 产品更极端的克制，功能第一、低培训成本，用户是被迫使用的员工。

## 适用场景

- 企业内部管理系统、ERP、业务工作台。
- 政企办公系统、行政/审批系统。
- 面向内部员工的后台工具（非对外产品）。
- 信息极密集、以「不出错、高效率」为唯一目标的界面。

## 不适用场景

- 对外 SaaS 产品（要好用 + 有品牌感）——用 `web.interface-design`。
- 营销/创意网页——用 `web.frontend-design`。
- 落地实现——用 `web.frontend-implementation`。

## 执行前需要的信息

- 系统的业务领域和主要用户角色。
- 权限/角色结构。
- 合规/浏览器兼容/遗留系统约束。

## 执行流程

1. 复用 `web.interface-design` 的通用系统原则（信息密度、一致性、token、数据展示、状态）。
2. 在其上应用企业取向：极致克制、低认知负荷、低培训成本、稳定优先。
3. 处理企业专属关注点：RBAC 权限、审计追溯、遗留兼容、合规、批量操作、密集表格表单。
4. 视觉基线：中性配色、Lucide 图标、禁 emoji、近乎无感的动效。
5. 落地交给 `web.frontend-implementation`。

## 交付结果

- 企业系统的设计方向（在通用系统原则之上的克制取向）。
- 权限/审计/批量/密集数据的处理方案。
- 落地方向。

## 默认边界

- **读文件**：是。**写文件**：是。**执行命令**：是（可选预览）。**网络**：否。
- 定企业系统取向和专属关注点；通用原则见 interface-design；落地交给 implementation。

## 与相邻 Skill 的区别

| Skill | 位置 |
| --- | --- |
| `web.enterprise-design` | 谱系最克制端——企业内部系统（SAP/Carbon/Ant Pro） |
| `web.interface-design` | 中段——SaaS 产品，好用 + 品牌感（Linear/Stripe） |
| `web.frontend-design` | 最冲击端——营销/创意网页（Awwwards） |

## 行为案例

### 案例 1：典型成功场景

**输入**：用户说「帮我设计一个集团 ERP 的采购审批模块」。

**预期行为**：
1. 复用通用系统原则（表格、表单、状态、token）。
2. 应用企业取向：密集专业、低培训（贴合用户已熟悉的审批流惯例）、去装饰。
3. 处理专属关注点：审批角色的权限矩阵、审批链的审计留痕、批量审批、多级表头的采购明细表。
4. 中性配色 + Lucide + 禁 emoji + 克制动效。
5. 落地交给 `web.frontend-implementation`。

### 案例 2：边界场景（要求加品牌打磨/新潮交互）

**输入**：用户说「给这个内部 ERP 整点 Linear 那种漂亮的品牌感和新潮交互」。

**预期行为**：
1. 提示：企业内部系统的用户是被迫使用的员工，新潮交互 = 增加培训成本和认知负荷。
2. 建议保持克制，把有限的视觉预算用在「减少出错」而非「变漂亮」。
3. 若确实是对外 SaaS 产品（可以有品牌感）→ 路由到 `web.interface-design`。
4. **不得**给内部 ERP 套新潮交互和品牌打磨而牺牲效率与低培训。
