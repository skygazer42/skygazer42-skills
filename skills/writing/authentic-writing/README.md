# Authentic Writing（去 AI 味写作）

## 一句话定位

写出有作者真实声音、去掉 AI 味的文章——不靠删表面 AI 特征，而靠作者档案 + 分类型写法 + 多轮独立审稿 + 规则迭代。

## 适用场景

- 写公众号、博客、观点文、教程等有个人风格的内容。
- 用户抱怨文章「有 AI 味」「不像我写的」。
- 想建立一套稳定复用的个人写作系统，而非一次性提示词。

## 不适用场景

- 纯功能性文本（API 文档、报错信息）——不需要作者声音。
- 只想快速删几个 AI 句式的一次性任务——一条提示词就够，不必上系统。
- 代码/技术实现——用对应的 engineering/web/backend Skill。

## 执行前需要的信息

- 作者档案：经历、视角、和读者的关系、事实边界、禁用表达（有多少给多少，会在迭代中完善）。
- 文章类型（教程 / 观点文 / …）和主题。
- 已有的初稿或写作意图。

## 执行流程

1. 建立/读取三层规则：作者是谁（含事实边界）、这类文章怎么写、绝对不写什么。
2. AI 写初稿（视为 60 分的第一版材料）。
3. 多轮独立审稿：轮1 任务完成度 → 轮2 像不像这个作者 → 轮3 AI 腔与禁忌；每轮独立子 Agent、重读对应规则。
4. 作者定夺每轮的接受/保留。
5. 把暴露的新问题（反复、影响大、可复用的）补回规则；冲突合并、过时替换。

## 交付结果

- 一篇有作者声音、经多轮审稿的成稿。
- 更新后的个人写作规则（作者档案 / 类型规则 / 禁用表达）。

## 默认边界

- **读文件**：是。**写文件**：是（初稿、改稿、规则文件）。**执行命令**：否。**网络**：否。
- **事实边界不可越**：不替作者编经历、下超出其了解范围的判断、用不符身份的权威口吻。
- **作者定夺**：审稿发现问题，但最终判断和成稿由作者决定。

## 行为案例

### 案例 1：典型成功场景

**输入**：用户说「帮我写一篇讲我创业踩坑的公众号，别有 AI 味」。

**预期行为**：
1. 先问/读作者档案：这段创业经历的事实边界（哪些能第一人称讲、哪些是听来的）。
2. 按「观点文」类型标准写初稿。
3. 三轮独立审稿：任务完成度 → 像不像作者 → AI 腔与禁忌（尤其查有没有替作者编细节）。
4. 每轮让作者定夺。
5. 把这次发现的、作者反复删的口吻补进禁用表达。

### 案例 2：边界/失败场景（身份越界）

**输入**：初稿里 AI 替作者写了一段「我当年在大厂带百人团队」，但作者并没有这段经历。

**预期行为**：
1. 第三轮审稿**必须抓出身份越界**——这是编造经历。
2. 删掉或改为作者真实位置能讲的表述。
3. **不得**因为「读起来更有说服力」就保留编造的经历。
4. 超出作者了解范围的判断，标注需作者确认，不替他下。
