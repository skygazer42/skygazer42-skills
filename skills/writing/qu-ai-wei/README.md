# 去 AI 味（qu-ai-wei）

## 一句话定位

清理简体中文的 AI 写作痕迹，保留事实、原意、语体和原文声口——不把所有文本拉成聊天风。

## 适用场景

- AI 生成的简体中文初稿需要自然化（报告、博客、邮件、PR 描述、文档）
- 用户说「去 AI 味」「改得说人话」「太生硬了」「humanize 中文」
- 作为更大工作流中的去机器感步骤（内嵌模式只输出终稿）

## 不适用场景

- 从零翻译或新写中文
- 繁體中文文本
- 只查错别字（纯校对）
- 真人文本换声口
- 绕过 AI 使用规定

## 执行前需要的信息

- 待编辑的简体中文文本
- 可选：2-3 段个人写作样本（用于语音校准）
- 可选：目标语体/发布场景（不确定时 qu-ai-wei 会主动提问）

## 执行流程

1. **敏感信息门检**：检测密码、API key、token 等凭证，命中即停止
2. **真人停手门检**：检查自纠、犹疑、方言、个人细节等真人信号，命中即停手
3. **语体激活**：默认书面语体；按不同语体激活 51 类模式的不同子集
4. **改写 + 自审**：初稿 → 多维度自审 → 终稿（过程中不编造事实）
5. **打磨报告**（普通模式）：动词强化、节奏重塑、填充切除、抽象换具体、语序归位的统计
6. **内嵌模式**：只输出终稿正文

## 交付结果

- **普通模式**：门检 → 初稿 → 自审 → 终稿 → 打磨报告
- **内嵌模式**：只输出终稿正文

## 默认边界

- **读文件**：是（按需读取参考文件）
- **写文件**：否
- **执行命令**：否
- **网络**：否
- **事实边界不可越**：不发明数字、人物、事件、引用；不补写原文没有的观察和判断

## 与相邻 Skill 的区别

| Skill | 区别 |
| --- | --- |
| `writing.humanizer` | 英语文本去 AI 模式；qu-ai-wei 是中文对应物，但有 51 类模式 + 9 档语体矩阵，更精细 |
| `writing.authentic-writing` | 建立作者声音系统 + 多轮审稿，重创作；qu-ai-wei 是战术层面的 AI 模式消除 |
| `writing.chinese-documentation` | 排版格式规范（中英空格、全半角标点）；qu-ai-wei 管语言表达自然化 |

## 行为案例

### 案例 1：典型去 AI 编辑

**输入**：
> 在快速变化的时代背景下，团队围绕提质增效开展了系统化实践。值得一提的是，本季度发布了 3 个版本，修复了 17 个线上问题，进一步赋能了组织协同。

**预期行为**：
1. 门检判断为 AI 文本
2. 识别命中 #3（时代开场）、#2（空洞强调）、#7（高频词「赋能」）
3. 删除无信息增量的背景、强调和口号
4. 保留数字与动作，不补写措施或效果

**合格终稿**：
> 本季度，团队发布了 3 个版本，修复了 17 个线上问题。

### 案例 2：真人文本停手

**输入**：
> 我到楼下才想起来钥匙还在桌上。站了两秒，又觉得有点好笑——这周已经第二次了。

**预期行为**：门检命中自嘲 + 个人细节 + 破折号停顿 → 判断为真人文本，停手，不改写。

### 案例 3：内嵌模式（只输出终稿）

**输入**：用户说「用 qu-ai-wei 改写下面的 PR 描述，只输出终稿正文」

**预期行为**：内部跑完整流程（门检→改写→自审→终稿），对外只输出终稿正文，不输出门检、初稿、报告。
