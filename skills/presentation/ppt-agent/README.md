# PPT Agent（端到端 PPT 生成流水线）

## 一句话定位

把"人类顶级 PPT 团队"的工作流固化成七阶段流水线：需求调研→大纲→资料检索→策划稿→整页 SVG 设计→预览出片→视觉 QA。产出原生可编辑 .pptx + 网页预览。

## 核心信条

**PPT 的灵魂是内容，不是皮囊。** 先想清楚为谁做、做什么、达到什么目的，再谈设计。

## 适用场景

- 从零创建演示文稿（汇报/答辩/路演/组会/课堂/产品介绍）
- 用户说「帮我做一套关于 XX 的 PPT」「把这个主题做成幻灯片」
- 需要两道人审把关（需求确认 + 大纲确认）的内容驱动 PPT 制作

## 不适用场景

- 起点是已有 .pptx 模板的逐元素编辑/提取——那是 `pptx` 技能的活
- 需要精确 OOXML 控制的单页排版——用 `presentation.open-kimi-ppt` 的 PPTD DSL
- 品牌视觉系统设计——转 `web.brandkit`

## 七阶段流水线

| # | 阶段 | 关口 | 产出 |
|---|------|------|------|
| 1 | 需求调研 | 🛑 等用户确认 | `00-research.md` |
| 2 | 大纲 | 🛑 等用户确认 | `01-outline.json` |
| 3 | 资料检索 | 自动 | `02-content.md` |
| 4 | 策划稿 | 自动 | `03-plan.md`（含风格令牌）+ 复杂页线框 |
| 5 | SVG 设计 | 自动 | `slides/slide-NN.svg` |
| 6 | 预览 + 出片 | 自动 | `preview.html` + `<主题>.pptx` + `README.md` |
| 7 | 视觉 QA | 自动 | 渲染检查 → 修复 → 重出片 |

## 执行前需要的信息

- PPT 主题
- 可选：已有大纲/内容素材（走快速通道跳过已完成阶段）
- 可选：目标风格（学术/商务/科技/发布风等）

## 交付结果

- `<主题>.pptx`：逐元素翻译为原生 PowerPoint 形状，打开即可改字改色
- `preview.html`：网页预览，方便通览全部页面
- `slides/`：1280×720 整页 SVG 源文件
- 各阶段过程稿（`00-research.md` / `01-outline.json` / `02-content.md` / `03-plan.md`）
- `README.md`：使用说明

## 默认边界

- **读文件**：是
- **写文件**：是（生成幻灯片 + 过程稿）
- **执行命令**：是（python3 脚本）
- **网络**：是（阶段 1、3 调研与检索）
- **事实边界**：需求调研联网搜索，不编造数据

## 与相邻 Skill 的区别

| Skill | 区别 |
| --- | --- |
| `presentation.open-kimi-ppt` | 基于 PPTD DSL 格式，格式先行；ppt-agent 是内容驱动流水线，内容优先 |
| `web.brandkit` | 品牌视觉板生成；ppt-agent 是完整多页 PPT 制作 |
| `presentation` 系列 | ppt-agent 和 open-kimi-ppt 是本仓库仅有的两个 PPT 生成能力，互补使用 |

## 行为案例

### 案例 1：典型 PPT 创建

**输入**：用户说「帮我做一个关于 WebAssembly 2026 生态现状的 PPT，15 页，给技术团队内部分享用」。

**预期行为**：
1. 联网调研 WebAssembly 最新进展
2. 问 3-5 个关键问题（听众水平、侧重点、已有素材等）
3. 等用户确认需求后，生成大纲并以便利贴形式展示
4. 等用户调整大纲后，自动完成检索→策划→SVG 设计→出片
5. 视觉 QA 通过后才交付 .pptx

### 案例 2：快速通道（已有大纲）

**输入**：用户提供了已确认的逐页大纲和内容素材。

**预期行为**：将已有材料整理为过程稿格式直接落盘，从阶段 4（策划稿）开始跑，不重复问需求和重新生成大纲。

### 案例 3：内嵌模式（在其他 Skill 中调用）

**输入**：`writing.authentic-writing` 的作者写完一篇长文后，需要将其转为演讲 PPT。

**预期行为**：ppt-agent 以长文内容为素材，跳过资料检索阶段，直接进入策划→设计→出片。
