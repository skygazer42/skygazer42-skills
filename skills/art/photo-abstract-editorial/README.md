# Photo Abstract Editorial（照片抽象编辑）

## 一句话定位

把一张上传照片变成「原始摄影区域 + 从照片推导出的极简抽象记忆面板 + 诗意英文标题」的竖向编辑作品。它保留照片的真实内容，并只从照片本身提炼空间、节奏与色彩关系——不是滤镜、照片重画或风格迁移。

## 适用场景

- 用户上传一张照片，要求「做成摄影与抽象面板结合的编辑作品」「抽象海报」「视觉记忆面板」「极简档案式海报」
- 需要一张不引入虚构元素、抽象图形必须能追溯到照片真实事实的作品
- 用户需要可直接用于图像生成模型的中/英文完整提示词（`references/` 下的文件可直接作为生成提示词）

## 不适用场景

- 网站页面、品牌视觉体系、交互界面设计（转 `web.frontend-design` / `web.interface-design` / `web.brandkit`）
- 从设计图还原为前端代码（转 `web.image-to-code` / `web.frontend-implementation`）
- 演示文稿生成（转 `presentation.open-kimi-ppt`）
- 对照片做风格化滤镜、重绘、扩图或增强——本 Skill 明确禁止改变照片内容
- 从零凭空设计一张抽象画（本 Skill 要求抽象图形必须从照片推导）

## 执行前需要的信息

- 一张待处理的照片（用户上传，作为唯一内容来源）
- 可选：审美偏好——照片/面板比例、色彩倾向、抽象形式（色块/弧形笔触/短条等）、版式与标题方向
- 可选：期望的抽象程度（关系优先 vs 保留少量身份特征）

## 执行流程

1. **内部解析照片**：识别 3–6 个决定性空间事实——主体关系、比例、轴线、方向、间隔、遮挡、纵深、节奏、光、色彩角色、负空间。
2. **保留摄影区域**：照片放在成品上方或主要区域，只允许克制等比缩放或轻微裁切，绝不重画、扩展、替换、修饰或加滤镜。
3. **提炼抽象母题**：在下方用极简抽象形式重建被保留的关系——优先表达关系而非轮廓，只为独特主体保留最低必要辨识度。
4. **拼接与版式**：竖向作品，象牙色均匀面板，照片/面板比例按原图自适应（不机械对半），两者直接平接、无任何相框/投影/拼贴/样机效果。
5. **色彩系统**：只从照片提取颜色并降饱和、减少数量；一个主色、一个深色结构色、一个浅色中性色、最多一两个小面积强调色。
6. **标题**：从照片事实创作 2–5 个词的原创英文标题，仅放在抽象面板上，使用克制编辑感衬线字体；副标题仅在能增加语义层时使用。
7. **输出**：只返回完成的作品，不加任何评论、分析、标题选项、标签、日期、logo 或水印。

## 交付结果

- 一张完成的竖向编辑作品（照片区域 + 抽象面板 + 标题）
- 可直接作为图像生成提示词使用的中文/英文完整提示词（在 `references/` 中）

## 默认边界

- **读文件**：是（按需读取 `references/` 与 `assets/examples/`）
- **写文件**：否
- **执行命令**：否
- **网络**：否
- **内容边界不可越**：上传照片是唯一内容来源；不得引入照片外的场景、物体、颜色或象征；不得把示例图当作素材复用

## 行为案例

### 案例 1：典型成功——照片转编辑作品

**输入**：用户上传一张城市天际线照片，说「用 photo-abstract-editorial 做成摄影与抽象面板结合的编辑作品」。

**预期行为**：
1. 照片以原图形式保留在成品上方，内容未被重画或加滤镜
2. 抽象面板为均匀象牙色（如 #F3F0E8），母题从照片的轴线、塔身收分、天际线节奏推导
3. 只提取照片中真实存在的颜色并降饱和
4. 面板上只出现一个 2–5 词的原创英文标题（衬线字体）
5. 成品无任何附加文字、标签、水印、标题选项或分析说明

### 案例 2：边界——不引入虚构元素

**输入**：用户上传一张极简静物照片，但要求「加一圈金色边框和 2024 字样」。

**预期行为**：拒绝添加照片中不存在的装饰（金色边框、日期字样属于无来源元素），并说明抽象面板背景必须均匀、无相框效果、无附加文字；仅当用户撤回到允许范围内时才继续。

### 案例 3：失败——禁用改图

**输入**：用户要求「把这张照片重绘成水彩风格」。

**预期行为**：说明本 Skill 不是滤镜或重画工具，照片区域必须忠实保留原图内容；此类请求应交给通用图像生成或风格化工具处理。
