## 一句话定位

在现有后端架构内安全实现 API、服务、任务、数据变更和外部集成，并明确验证边界。

## 适用场景

- 新增或修改 HTTP、RPC 或其他服务端接口。
- 修改业务服务、后台任务、队列消费者或定时任务。
- 新增数据访问、Schema、约束或 Migration。
- 连接新的外部服务或 Provider。
- 修改后端配置与错误处理。
- 为后端功能增加聚焦测试。

典型请求：

```text
使用现有服务层和数据库层实现订单创建接口，并处理重复请求和事务完整性。
```

## 不适用场景

- 只需要审查后端变更：使用 `backend.backend-review`。
- 只需要定位现有故障根因：使用 `backend.backend-debugging`。
- 主要修改页面、组件或客户端数据流：使用 `web.frontend-implementation`。
- 涉及生产写入、破坏性 Migration 或不可恢复操作但没有明确授权与恢复方案。

## 执行前需要的信息

- 用户目标、验收标准和兼容性要求。
- 真实入口、调用方、接口契约和错误约定。
- 模型、Schema、Migration、配置和现有测试。
- 认证、授权和资源所有权规则。
- 外部服务契约、Sandbox 或可替代的本地测试边界。
- 类型、Lint、测试、Migration 和集成检查命令。

## 执行流程

1. 阅读请求、入口、调用方、契约、数据模型、配置和测试。
2. 追踪从不可信输入到验证、授权、业务逻辑、持久化、外部调用和响应的完整路径。
3. 在修改前明确认证、授权、秘密和错误暴露等信任边界。
4. 在现有架构内实现最小完整改动，默认保持向后兼容。
5. 根据真实路径处理约束、事务、幂等、并发、超时和有限重试。
6. 为成功路径、重要失败路径和回归风险添加最小测试。
7. 运行聚焦检查，并分开报告本地验证与部署依赖验证。

## 交付结果

- 实际仓库代码和测试改动。
- 对外契约、Schema、配置或 Migration 的明确变化说明。
- 认证、授权、幂等、事务和错误处理方面的重要决定。
- 文件清单和精确检查命令。
- 已验证结果与仍需 Sandbox、数据库或部署环境验证的内容。

## 权限

| 权限 | 声明 | 用途 |
| --- | :---: | --- |
| 网络 | 否 | 当前通用流程不默认要求访问外部网络 |
| 读文件 | 是 | 阅读入口、服务、数据、配置和测试 |
| 写文件 | 是 | 实现代码、Migration、配置和测试 |
| 执行命令 | 是 | 运行测试、类型、Lint、Migration 和集成检查 |

具体任务若要求访问外部 Provider 或远程环境，仍需按任务另行确认；Manifest 不等于预先授权生产访问。

## 默认边界

- 不为了缩短实现弱化输入验证、授权、约束或错误处理。
- 不写入凭据，不记录敏感值，不静默吞掉失败。
- 现有代码或标准库足够时，不新增依赖和抽象。
- 未明确接受时，不引入破坏性接口变化。
- 没有授权和恢复方案时，不执行破坏性 Migration 或生产写入。

## 失败时如何处理

外部服务、数据库、凭据或部署环境不可用时，只实现能够从现有契约验证的部分，保留失败证据，并明确列出尚未完成的集成检查。不能声称远程系统已经接受请求。

## 行为案例

当前案例位于 [`tests/cases.yaml`](tests/cases.yaml)：

- `protects-write-endpoint`：订单写接口必须检查认证授权、输入、幂等和事务完整性。
- `reports-unverified-integration`：外部 Sandbox 不可用时，只验证本地边界并披露远程验证缺口。

## 与相邻 Skill 的区别

```text
Backend Implementation：实现或修改后端行为
Backend Review：        默认只读，审查风险
Backend Debugging：     从现有故障证据定位根因
```
