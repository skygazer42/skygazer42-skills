## 一句话定位

通过安全复现、端到端追踪和有区分力的假设验证，找出后端故障根因及影响范围。

## 适用场景

- API 返回 4xx、5xx 或异常响应。
- 后台任务失败、卡住或偶发超时。
- 数据出现不一致、遗漏或重复。
- 队列、缓存或外部集成发生故障。
- 同一问题只在特定环境、配置或数据形状下出现。
- 用户需要根因、影响范围和验证方案，而不是立即试错改代码。

典型请求：

```text
定位订单导出任务偶发超时的根因，先不要修改代码，并说明影响范围和下一步验证。
```

## 不适用场景

- 目标是实现一个新后端功能：使用 `backend.backend-implementation`。
- 目标是审查尚未发布的后端 diff：使用 `backend.backend-review`。
- 目标是直接修复，且根因已经明确：使用实现类 Skill。
- 没有任何日志、堆栈、复现或仓库证据，却要求给出绝对确定结论。

## 执行前需要的信息

- 准确症状、期望行为、环境和发生时间。
- 请求、任务、Trace、记录或其他可关联标识。
- 日志、错误、指标、堆栈和最近变更。
- 真实入口、调用链、配置、队列、存储、缓存和外部服务代码。
- 可安全运行的复现命令、请求或测试。
- 对生产数据和远程环境的明确授权范围。

## 执行流程

1. 固定症状、预期、环境、时间和现有证据。
2. 找到真实入口，追踪调用方、配置、队列、存储、缓存和外部服务。
3. 使用最小安全命令、请求或测试复现，并保存原始输出。
4. 检查相关日志、指标、最近变更、环境差异和数据形状。
5. 建立一个短的优先假设列表。
6. 对每个假设运行成本最低、最能区分真假的检查。
7. 说明根因、触发条件、相邻受影响路径以及现有防线为何没有发现。

## 交付结果

- 根因和置信度。
- 复现步骤或决定性证据。
- 触发条件和影响范围。
- 已确认事实、有证据推断和未知项的明确分隔。
- 最小修复建议和验证计划。
- 未执行的恢复、修复或生产检查。

默认只诊断，不自动实现修复。

## 权限

| 权限 | 声明 | 用途 |
| --- | :---: | --- |
| 网络 | 否 | 默认使用本地仓库和已有证据 |
| 读文件 | 是 | 阅读代码、配置、日志和测试 |
| 写文件 | 否 | 诊断模式默认不修改代码 |
| 执行命令 | 是 | 运行安全复现和区分假设的检查 |

生产日志、数据库或远程服务访问不由此 Manifest 自动授权，必须遵守用户给出的具体范围。

## 默认边界

- 有只读检查时，不通过修改代码来试探猜测。
- 不把重启、重试、清缓存或增大超时称为根因。
- 不超出授权查询或修改生产数据。
- 不输出凭据、Token、个人数据或完整敏感 Payload。
- 不在无法复现或证据不足时编造确定结论。

## 失败时如何处理

无法复现时，保留当前最强证据，缩小可能条件，并指出下一条最有价值的观察。缺少日志或运行权限时，给出安全的下一步诊断，不声称已经知道唯一根因。

## 行为案例

当前案例位于 [`tests/cases.yaml`](tests/cases.yaml)：

- `traces-intermittent-timeout`：对偶发任务超时追踪配置、排序假设并评估影响范围。
- `refuses-unsupported-cause`：只有堆栈片段时区分事实和推断，不给出虚假确定根因。

## 与相邻 Skill 的区别

```text
Backend Debugging：     从故障症状出发定位根因
Backend Review：        从代码变更出发寻找风险
Backend Implementation：在根因或需求明确后修改系统
```
