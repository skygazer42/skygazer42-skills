# 探索性数据分析（Exploratory Analysis）

## 一句话定位

对用户提供的**本地数据文件**（CSV/TSV/JSON/Parquet/XLSX）或对话内表格做探索性分析——数据画像、质量问题识别、关系与模式发现、维度/度量建议、后续分析推荐，以及分享前的方法论与偏差审查。**默认只读**：不清洗、不填补、不删异常值、不覆盖源文件。

## 适用场景

- 拿到一个从未见过的新数据集，先弄清形状、质量和模式
- 检查缺失率、列分布、基数、重复记录
- 发现可疑值、占位符、格式不一致、编码问题
- 判断哪些列适合做维度/度量、哪些时间列适合趋势分析
- 分享分析给利益相关者前做质量与偏差审查

## 不适用场景

- 从数据库/数据仓库查询数据 → v0.1 不支持，数据库查询为未来能力
- 自动数据清洗、填补、异常值移除 → 超出只读边界
- 数据可视化图表生成 → 属可视化能力，本 Skill 只画像和审查
- 从零新建数据集 → 本 Skill 分析已存在的数据

## 执行前需要的信息

- 本地数据文件（CSV/TSV/JSON/Parquet/XLSX）或对话内表格
- 可选：分析目标（探索方向、关心的质量维度、分享场景）
- 无数据时：向用户要数据，不编造、不联网猜

## 执行流程

1. **读取数据**：读取文件/表格，推断列类型，记录行数列数
2. **理解结构**：按类型分类每列（标识符/维度/度量/时间/文本/布尔/结构）
3. **生成数据画像**：表级指标 + 逐列画像（缺失率/基数/top 值/数值分位数/字符串/日期/布尔）
4. **识别质量问题**：高缺失率、基数意外、可疑值、重复、偏斜、编码
5. **发现关系与模式**：外键候选、层级、相关性、派生/冗余列
6. **建议维度与度量**：最佳维度列、关键度量、时间列、自然分组
7. **推荐后续分析**：3-5 个具体可执行的分析
8. **分享前审查**（可选第二流程）：方法论/陷阱目录/计算复核/可视化/结论 → 信心评级

## 交付结果

- **Data Profile**：Overview（行数列数日期范围）+ Column Details + Data Quality Issues + Recommended Explorations
- **分享前审查**（如要求）：Validation Report，含 Overall Assessment（可分享/带注记分享/需修订）、Issues Found、Calculation Spot-Checks、Suggested Improvements、Required Caveats
- 报告可另写为 Markdown/JSON 文件，**不改写源数据**

## 默认边界

- **读文件**：是
- **写文件**：是（仅另写报告，不覆盖源数据）
- **执行命令**：是（python3 数据脚本）
- **网络**：否
- **事实边界不可越**：一切统计基于实际读到的数据，不编造；质量旗标是启发式的

## 与相邻 Skill 的区别

| Skill | 区别 |

## 行为案例

### 案例 1：典型探索

**输入**：用户上传 `users.csv`，说「先帮我看看这份数据再决定怎么分析」。

**预期行为**：
1. 读取文件，报告 2,340,891 行、23 列
2. 分类列：8 dimensions、6 metrics、4 dates、5 IDs
3. 输出逐列画像（缺失率、基数比、top 值、分位数）
4. 标记质量问题：`created_at` 有 0.2% 缺失、`status` 出现 340 行 "UNKNOWN" 可疑值
5. 建议：plan_type、signup_source、country 是高价值维度
6. 推荐 3-5 个后续分析（趋势、分布深入、相关分析、队列分析）
7. 不修改 `users.csv`

### 案例 2：无数据 / 数据库请求

**输入**：用户说「帮我探索一下生产库的 orders 表」，未提供文件。

**预期行为**：
1. 明确说明 v0.1 只处理用户提供的本地文件或对话内表格
2. 数据库查询标注为未来能力，不假装具备
3. 不伪造连接、不编造表结构或查询结果

### 案例 3：分享前审查

**输入**：用户说「这份季度收入分析在发给高管前帮我检查一下」，附分析文档。

**预期行为**：
1. 检查幸存者偏差、不完整期对比、分母漂移等陷阱
2. 独立复核关键数字（小计=合计、百分比≈100%）
3. 若 Q4 窗口比 Q3 短：标记需注记，评级"带注记分享"
4. 列出必须传达给高管的注记
